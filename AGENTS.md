# Repository Workflow

- Always begin from the latest `main`.
- Use one temporary branch per task.
- Open pull requests directly against `main`.
- Never stack a new task on an unmerged feature branch.
- Never reuse an old feature branch.
- Do not push directly to `main`.
- Run backend tests and the frontend production build before completing a task.
- Keep pull requests narrowly scoped.
- Do not alter established staffing, seniority, preference, chair-decision, audit, or authorization rules unless the task explicitly requires it.
- Preserve backward compatibility unless a migration or breaking change is expressly approved.
